Overview

Tic-tac-toe is a two-player alignment game, also called noughts and crosses, Xs and Os, and regionally Exy Ozys. Nought means zero; cross describes the X. The game has no chance events or hidden information. Careful play by both sides ends in a draw.

This application offers local two-player play and a perfect-play computer. The computer is a C search algorithm running locally through WebAssembly, not a remote AI service. It requires no account or API key.

Rules and controls

  1. X starts in this implementation; starting-player conventions can differ elsewhere.
  2. Players alternate placing their mark in an empty cell.
  3. Three matching marks in a row, column, or diagonal win immediately.
  4. A full board with no winner is a draw. Terminal rounds reject further moves.

Choose A friend or Computer. In computer mode, choose X to open or O to let the computer start. Restart Round retains scores; New Match clears them. Changing opponent or mark starts a fresh match. Game state is not saved across reloads.

Use Tab and Enter or Space for keyboard play. The status announces turns and results. Dark, Light, and System themes apply to both game and docs; an explicit theme choice is saved when local storage is available.

Strategy

Start by looking for an immediate win. Otherwise stop an immediate opposing win. Next consider a fork: a move that creates two independent winning threats. Blocking a fork may require a forcing threat that makes the opponent defend, rather than merely occupying one possible fork cell.

After wins, blocks, forks, and fork defenses, useful positional priorities are the center, a corner opposite an opposing corner, another empty corner, and then an empty edge. These priorities are a guide, not a replacement for examining continuations.

Opening families

Rotations and reflections reduce the nine opening cells to three types: center, corner, and edge. Against a corner opening, take the center. Against a center opening, take a corner. Against an edge opening, the center, an adjacent corner, or the opposite edge can preserve a draw with correct continuation.

Recognizing a fork

1 | 2 | 3
---------
4 | 5 | 6
---------
7 | 8 | 9

Suppose X owns 1 and 9 while O owns 5. O should choose an edge. If O chooses 3 instead, X can play 7 and threaten both 4 and 8. One defensive move cannot cover both. This example explains why another corner is not always a good move.

A draw against perfect play is a successful defensive result. An unbeatable computer cannot guarantee a win against an opponent who also plays perfectly.

The m,n,k family uses an m-by-n board and a target of k aligned marks; this game is 3,3,3. Higher-dimensional and more general incidence or hypergraph models replace ordinary rows with designated winning sets.

History

Ancient Egyptian and Roman three-in-a-row boards are historical relatives, but a board pattern alone does not establish modern placement rules. Roman terni lapilli limited each player to three pieces and involved movement. Three men's morris and Picaria are related games rather than alternate names for identical rules.

Nineteenth-century print records include noughts and crosses in 1858. A game named tick-tack-toe was recorded in 1884, but described a different eyes-closed slate-scoring activity. The history of a name is therefore not the same as the history of today's rules; proposed links with the older backgammon name tick-tack are etymological suggestions.

In 1952, Sandy Douglas developed OXO for Cambridge's EDSAC, an early graphical computer game with a perfect-play opponent. A later Tinkertoy computer demonstrated that a mechanical construction could implement perfect play too. The tiny game tree makes the game useful for teaching search and artificial intelligence.

Variants and related games

  • Three-dimensional play adds spatial lines. Qubic uses a 4-by-4-by-4 board; its solved result differs from ordinary 3-by-3 play.
  • Misère reverses the objective: making your own line loses. Wild play lets either player choose either mark.
  • Number Scrabble, or Pick15, has players claim unused numbers 1–9 and seek three totaling 15. Mapping the numbers to a 3-by-3 magic square reveals the correspondence to winning lines.
  • Word-based versions use selected words and common letters to encode the same winning combinations.
  • Numerical tic-tac-toe uses odd and even number sets and a target sum of 15 on a line; it is distinct from simply claiming numbers in Pick15.
  • Check Lines uses eleven holes, intersecting lines, limited tokens, and later movement. Other variants require two completed lines instead of one.
  • Quantum-inspired play introduces unresolved linked moves and resolution rules. This website does not implement quantum computation.
  • Gomoku, pente, Connect Four, Quarto, Gobblet, Order and Chaos, Toss Across, and morris games share alignment ideas but change placement, pieces, or objectives.

These are documentation topics, not selectable game modes.

Culture and learning

The 1983 film WarGames uses repeated draws as a metaphor for conflict with no winning outcome. Hollywood Squares, Tic-Tac-Dough, and related television formats connect trivia answers to claiming squares. Other adaptations combine pricing guesses or physical ball placement with a grid objective.

The game also appears in nineteenth-century song and in stories about trained arcade animals. An apparent animal opponent need not be independently choosing moves; computerized signaling and conditioning can explain such demonstrations.

For learning, predict a threat before moving, explain a fork in two different ways, and compare a board with its reflection. The game can teach sportsmanship and recognizing when avoiding defeat is the best possible result.

C engine and API

C owns the board, turn, result, winning-cell markers, mode, human side, and scores. JavaScript loads WebAssembly, forwards events, reads C getters, and renders the interface. No game rules or computer move selection run in JavaScript.

Cells: 0 empty, 1 X, 2 O. Results: 0 ongoing, 1 X win, 2 O win, 3 draw. Modes: 0 local, 1 computer. Invalid indexed getters return -1.

Minimax through negamax

Search scores every continuation from the player-to-move's perspective and negates a child's score at its parent. Wins outrank draws, which outrank losses. Depth favors faster wins and later losses; ties favor center, corners, then edges. A private search board prevents speculative scoring or live-board mutation.

The browser's short computer delay is presentation only. Resetting or reconfiguring cancels its timer and changes a generation token, while C independently enforces ownership and terminal state.

Development and deployment

Install a C11 compiler, Make, Python 3, Node.js, and Emscripten. Activate SDK 3.1.57 and source its environment. Serve the build over HTTP, not file://.

git clone https://github.com/emscripten-core/emsdk.git
cd emsdk
./emsdk install 3.1.57
./emsdk activate 3.1.57
source ./emsdk_env.sh
# In the game repository:
npm ci
npx playwright install --with-deps chromium
make test-native
make build
npm test
python3 scripts/count_states.py
python3 -m http.server 8080 --directory dist

Open localhost:8080. The build produces game.js, game.wasm, static interface assets, and docs/index.html inside dist. Edit this documentation in public/docs/index.html; it is a standalone static page, not a server application.

CI retains Ubuntu 24.04 for the pinned browser-testing toolchain. Browser tests serve real WebAssembly under /tic-tac-toe/ and exercise both modes, resets, themes, docs, and mobile navigation. Native tests explore every human continuation against the deterministic computer as either side.

Choose GitHub Actions as the Pages publishing source. Branch builds validate changes; only the default branch deploys. The game is at /tic-tac-toe/ and these docs at /tic-tac-toe/docs/. Relative assets also support local root hosting. A passing branch build does not itself publish the website.

Troubleshooting

  • Loading error: inspect game.js and game.wasm requests and confirm both are in the artifact.
  • Pages configuration Not Found: enable Pages with GitHub Actions in repository settings before retrying deployment.
  • Browser-install OS error: retain the Ubuntu 24.04 build runner.
  • Old interface: verify default-branch deployment and reload without cache.
  • Computer opens first: you selected O; this implementation always starts with X.
  • Lost scores after refresh: scores are intentionally in memory. Theme storage is separate and best-effort.
